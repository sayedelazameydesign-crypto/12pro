# Contributing to AGI-OS

Thank you for contributing to the 12-layer professional repository!

## 12-Layer Contribution Flow

```
Idea -> Issue -> Task -> Branch -> PR -> CI -> Review -> Merge -> Release
```

## Prerequisites

- Node >=20
- npm >=10
- Copy `.env.example` to `.env` (never commit real secrets)

## Development

```bash
npm ci
npm run build
npm run lint
npm run typecheck
npm run test:unit
npm run test:integration
npm run verify
```

## Branch Naming

- `feat/<scope>-<short>` e.g. `feat/planner-dag`
- `fix/<scope>-<issue>` e.g. `fix/memory-leak-123`
- `docs/<scope>` e.g. `docs/adr-0008`
- `chore/<scope>` e.g. `chore/ci-cache`

## Pull Request Requirements

All PRs must satisfy 12-layer checklist in `.github/PULL_REQUEST_TEMPLATE.md`:

- Lint ✅
- Typecheck ✅
- Unit ✅
- Integration ✅
- E2E ✅ (if UI/API)
- Security ✅
- Build ✅

No merge if required gate fails.

## Code Ownership

See `.github/CODEOWNERS`. Changes to sensitive paths need security-team review.

## ADR & RFC

- For architectural decisions: add `docs/adr/NNNN-title.md`
- For large features: add `docs/rfc/feature.md` and open Issue with `needs-rfc` label

## Certification

Every change should update evidence:

- Tests in `tests/`
- Benchmarks if perf impact
- Gates in `certification/gates/` auto-generated by CI

## Security

Never commit:

- `.env`
- `GEMINI_API_KEY`, `GROQ_API_KEY`, `HF_TOKEN`, etc.

Use `.env.example` with empty values + GitHub Secrets for CI.

See `SECURITY.md`.

## Commit Messages

Conventional Commits:

- `feat(planner): add DAG retry`
- `fix(runtime): handle timeout`
- `docs(adr): add 0008`
- `chore(ci): cache npm`

## Release

Only maintainers can tag:

```bash
npm run verify -- --strict
npm run certify
git tag vX.Y.Z
git push origin vX.Y.Z
```

`release.yml` handles publish + GitHub Release with certification manifest.
